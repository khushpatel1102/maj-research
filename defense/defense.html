Proposed Solution · What The Judge Sees

An end-to-end example.

Input
Task: "Explain key methods for determining the pre-money valuation of a tech startup before a Series A round."
Response: a 4-paragraph candidate answer covering DCF, comparable-company, and VC method.
Retrieve · 1
Contrastive Attempts  ·  cosine ≥ 0.85
Returned: 2 past responses that passed on similar valuation questions, 1 that failed.
Retrieve · 2
Similar Issues  ·  cosine ≥ 0.90
Returned: "missed discount-rate justification", "vague comparable-company criterion".
Retrieve · 3
Semantic Patterns  ·  cosine ≥ 0.90
Returned: recurring category — "incomplete-methodology" — observed across 4 past attempts.
Assemble
All three stages are formatted into a single context block — examples, issues, patterns — and prepended to the judge's prompt alongside the task and rubric.
Judge
GPT-4o receives task + rubric + retrieved context + candidate response, and returns a structured verdict (pass / fail + reasoning).

Proposed Solution · Builds #2 & #3

Two MCTS extensions.

Build #2 · Retrieval Layer
MCTS-Retrieval
Tree search over 7 retrieval actions on the graph — four of them multi-hop traversals (Issues→Fixes, Semantics→Issues, Policy→Attempts, Attempts→Semantics). Trajectories scored by relevance, diversity, volume.
Build #3 · Reasoning Layer
MCTS-Judge
Decomposes evaluation into 5–7 task-specific subtasks. Each rollout selects subtasks via UCT + LLM self-assessment. Final verdict aggregates the best trajectory.

Combined into six evaluation modes, ablating memory and search independently.

Proposed Solution · MCTS-Judge · Walkthrough

How tree-search reasoning runs.

Input
Task + Response. Same EvalsBench item as before.
Decompose
LLM dynamically generates 5–7 task-specific subtasks — each probes the response from a different angle.
e.g. "Does it cover DCF?" · "Is the discount-rate logic correct?" · "Does it mention founder share?"
Search
4 rollouts, max depth 5. At each step, the child node maximising UCT + LLM self-assessment is selected. Each leaf scores the response from that subtask's perspective.
Aggregate
Best trajectory's majority vote + a global synthesis over all visited subtasks.
Verdict
Structured output: { verdict: pass | fail, reasoning: ... }

Proposed Solution · The Leakage Problem

Two leakage channels.

Channel I
Paired-item leakage
Question Q
├─ Q.PASS → train
└─ Q.FAIL → test

The judge sees Q.PASS in memory
while scoring Q.FAIL.
Channel II
Write-back leakage
t=0   score A → write to memory
t=1   score B (related to A)
     memory now contains A's verdict

Every early write contaminates
every later read.
Proposed Solution · Build #4 · The Protocol

Closing both channels.

  • FIX ISplit by question, not row.
  • FIX IIFreeze memory during the test.

A claim is not a proof. How do I prove the freeze actually held?

Proposed Solution · The Two-Layer Audit

SHA-256 + runtime write-blocker.

Layer 1 · After-the-fact

SHA-256 fingerprint

before = sha256(graph)
    ... run evaluation ...
after = sha256(graph)
assert before == after
Layer 2 · During the run

Runtime write-blocking

graph.create = guard
graph.link = guard
graph.upsert = guard
FrozenMemoryViolation if called
Proposed Solution · The Audit · Walkthrough

How the audit runs.

Before
Take a deterministic snapshot: count nodes & edges by type, hash sorted node IDs + edge triples → SHA-256 fingerprint.
During
Patch every write method on the graph: create · link · upsert. Any attempted write raises FrozenMemoryViolation.
Run eval
All 80 test items judged. Memory should be read-only.
After
Take another snapshot. Compare to "before".
Verdict
Pass only if: fingerprints match exactly AND no FrozenMemoryViolation was raised. Otherwise the run is rejected.

Evaluation · Statistical Methodology

How significance is decided.

Every accuracy is reported with a two-sided Wilson 95% CI. Mode-versus-mode comparisons are paired and assessed with the exact McNemar test.

$$\mathrm{CI}_{\mathrm{Wilson}} \;=\; \frac{p + \tfrac{z^{2}}{2n} \;\pm\; z\sqrt{\tfrac{p(1-p)}{n} + \tfrac{z^{2}}{4n^{2}}}}{1 + \tfrac{z^{2}}{n}}$$ (3.4)
$$p_{\mathrm{McNemar}} \;=\; 2 \sum_{k=0}^{\min(b,c)} \binom{b+c}{k}\left(\tfrac{1}{2}\right)^{b+c}$$ (3.5)

A difference is declared significant only when the McNemar p-value < 0.05 and the paired bootstrap CI excludes zero.   $b, c$ = discordant pairs.

Proposed Solution · Build #5 · The Reliability Harness

Three independent stress tests.

Experiment B
Stochastic Stability
95%   90%
Same item, judged twice. MAJ and MCTS-Judge+Memory agree with themselves on the great majority of items. The modes are stable.
Experiment C
Label-Flip Discrimination
65% / 70% / 65%
Invert PASS↔FAIL and check the judge flips with it. All modes discriminate above chance — and similarly to each other.
Experiment D
Defense Filter
64.8%   65.0%
Similarity-threshold filter under 50% poisoned memory. The filter does not help. An honest negative result, reported as such.
Proposed Solution · Reliability Harness · Walkthrough

How each experiment runs.

Stability · B
For each item: judge it twice with the same memory.
Measure:   agreement rate.   "Does the system give the same answer to the same question?"
Label-Flip · C
For each item: generate an inverted response (LLM rewrites it to clearly fail), then judge the inverted version.
Measure:   how often the verdict correctly flips PASS → FAIL.
Defense · D
Build a 50%-poisoned memory. Compare two configurations: judge with the raw poisoned memory, vs. judge with a similarity-threshold filter applied on retrieved nodes.
Measure:   does the filter recover accuracy?
Verdicts
B: 95% / 90% — modes are stable.   C: 65% / 70% / 65% — all modes discriminate.   D: 64.8% vs 65.0% — the filter does not help.

Discussion · Threats to Validity · §5.9

Where the null holds — and where it doesn't.

Scope
One judge model.
All audited results use GPT-4o. A weaker model may have headroom for memory to help; a stronger one may not.
Power
n = 80, MDE ≈ 12–15 pp.
Powered to detect the conventional 6–10 pp claim, and didn't. A small genuine effect of a few points cannot be excluded — hence "no effect detected at this scale".
Domain
One benchmark, one task.
EvalsBench: rubric-graded QA in finance/startup. Open-ended or creative tasks may behave differently.
What Holds
The protocol itself.
The leakage-free audit is benchmark- and model-agnostic. The methodological contribution is independent of the empirical finding.
